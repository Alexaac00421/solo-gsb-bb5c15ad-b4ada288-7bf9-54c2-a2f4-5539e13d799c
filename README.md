# 离线定向赛计时裁决台

面向小型定向赛的**离线**网页计时与裁决系统。赛前录入检查点顺序、选手名单和带时区的发枪时刻；
批量导入刷卡 CSV，系统自动计点、判定完赛/未完赛、排名；裁判可作废误读记录并即时重算；
发布时冻结榜单及所依据的全部事件，之后的补传/作废只影响下一次发布，历史榜单随时可回看。

- 后端：Node.js（Express）+ SQLite（`better-sqlite3`，WAL，同步事务）
- 前端：单个原生 HTML/JS 页面，**无任何 CDN/外部资源**，断网可用
- 部署：Dockerfile + Docker Compose 一键启动，数据落 SQLite 文件卷持久化

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后用浏览器打开：

- **http://localhost:8080**

停止 / 查看日志 / 重新启动：

```bash
docker compose down          # 停止（数据保留在卷中）
docker compose logs -f       # 跟踪日志
docker compose up -d         # 再次启动
docker compose down -v       # 同时删除数据卷（清空全部数据，慎用）
```

不使用 Compose 时：

```bash
docker build -t orient-timing-bench .
docker run -d --name timing-bench -p 8080:8080 -v timing-data:/app/data orient-timing-bench
```

本地直接运行（需 Node.js ≥ 20）：

```bash
npm install
npm start
```

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST_PORT` | `8080` | Compose 宿主机暴露端口，如 `HOST_PORT=9090 docker compose up -d` |
| `PORT` | `8080` | 容器内监听端口 |
| `DB_PATH` | `/app/data/timing.db` | SQLite 数据库文件路径（已挂载持久化卷） |
| `TZ` | `Asia/Shanghai` | 容器时区（仅影响日志；时刻计算一律按时区偏移换算） |

## 使用流程

网页分四个页签：

1. **赛前配置**：录入
   - 发枪时刻（**必须带时区**，如 `2026-10-11T09:30:00+08:00`，也支持 `Z` / 空格分隔 / `±HHMM`）；
   - 检查点编号，每行一个、**按顺序且不重复，末项为终点**；
   - 选手编号，每行一个、不重复。
   - 一旦受理过刷卡事件或进行过发布，配置自动锁定（保证历史榜单可复现）。
2. **CSV 导入**：选择文件或粘贴内容后整批提交。
3. **实时裁决**：查看草稿榜单与每人全部刷卡明细；对误读单条记录点【作废】（可取消），榜单立即重算；页面每 5 秒自动刷新。
4. **发布与榜单**：发布当前成绩并冻结；在发布历史中【回看】任意一次冻结榜单及其事件快照。

## CSV 格式

UTF-8 编码，首行为表头（中/英文列名均可识别）：

| 列 | 可识别表头 |
| --- | --- |
| 事件号 | `事件号` / `event_id` / `eventId` / `id` / `记录号` 等 |
| 选手编号 | `选手编号` / `bib` / `runner` / `number` 等 |
| 检查点 | `检查点` / `cp` / `cp_code` / `checkpoint` / `control` 等 |
| 刷卡时刻 | `刷卡时刻` / `time` / `punch_time` / `timestamp` 等 |

无表头时按固定列序解析：`事件号,选手编号,检查点,刷卡时刻`。
时刻必须带时区，示例：`2026-10-11T09:31:05+08:00`、`2026-10-11 01:31:05Z`。
样例文件见 [`samples/punches.csv`](samples/punches.csv)。

### 整批校验规则（任一不满足 → 整批拒绝，页面列出每个错误的行号，不写入任何记录）

- 事件号非空且在本批中不重复；
- 选手编号、检查点必须存在于赛前名单（未知即拒绝并标注行号）；
- 时刻格式合法且带时区、取值不越界；
- 事件号已在库中但**内容不同**（选手/检查点/时刻任一不一致）→ 冲突，拒绝；
- 事件号已在库中且**内容完全相同** → 视为重传，幂等跳过，不重复入库、不报错。

重复刷卡、乱序刷卡不会被拒绝：原始记录全部保留，计点时标注为「重复 / 乱序(缺前点) / 发枪前」供复核。

## 计点与排名规则

- 按刷卡时刻升序，为每位选手**依次**为每个检查点选取：不早于发枪时刻、且严格晚于前一计点时刻的**最早一条**有效（未作废）记录；
- 任一检查点选不出记录即判 **未完赛（DNF）**，其后检查点不再计点；
- 完赛成绩 = 终点检查点刷卡时刻 − 发枪时刻；
- 排名：完赛者按 **耗时升序 → 终点时刻升序 → 选手编号升序**（纯数字按数值排序）；未完赛者列于其后（到点数多者在前）。

## 作废与发布的一致性

- 作废/取消作废是单条事务，提交后实时榜单立即按最新已提交事件集重算；
- 发布在单个 `BEGIN IMMEDIATE` 事务内完成「读取全部已提交事件 → 计算 → 写入榜单快照与事件快照」；
- 导入（整批事务，失败回滚）、作废、发布经 better-sqlite3 的同步事务串行化，
  任何一次发布看到的都是某个已完整提交的事件集合，失败不会留下部分状态；
- 发布之后新补传的事件、新的作废操作只改变实时草稿与**下一次**发布；冻结的旧榜单及其事件快照永不变化。

## HTTP API（可供脚本/命令行使用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查与计数 |
| `GET` / `PUT` | `/api/setup` | 读取 / 整批替换赛前配置（锁定后返回 409） |
| `POST` | `/api/imports` | 导入 CSV（`Content-Type: text/csv` 直接放 CSV 文本，或 JSON `{"csv":"..."}`） |
| `GET` | `/api/results/live` | 当前实时成绩与全部事件判定 |
| `POST` | `/api/events/:事件号/void` | 作废 `{"voided":true}` / 取消作废 `{"voided":false}` |
| `POST` | `/api/publications` | 发布冻结（可带 `{"note":"..."}`） |
| `GET` | `/api/publications` | 发布历史 |
| `GET` | `/api/publications/:id` | 回看某次冻结榜单及事件快照 |

命令行导入示例：

```bash
curl -s -X POST http://localhost:8080/api/imports \
  -H 'Content-Type: text/csv' \
  --data-binary @samples/punches.csv
```
